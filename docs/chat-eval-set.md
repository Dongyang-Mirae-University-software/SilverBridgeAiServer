# 의료 챗봇 평가 질문 세트 (2026-10-15)

응답 경로: 사용자 문장 → Claude 라우터(route/emergency) → `ChatService._force_emergency`(키워드 강제) → MedGemma(증상) 또는 예약 오케스트레이터.
키워드 층은 `tests/test_emergency_cases.py` 가 자동 검증하고, 예약 흐름(D절)은 `tests/test_reservation_confirm_*.py`·`test_reservation_date_ask.py`·`test_reservation_token_claim.py` 가 자동 검증한다. LLM 층(라우터·MedGemma)은 아래 기대값을 수동 또는 로그(`meta.router`, `meta.emergencySignals`)로 확인한다.

열 설명: route = 라우터 최종 경로, intent = 응답 `intent`, risk = `riskLevel`, 경고 = `emergencyWarning` 유무, advice = 말풍선 마지막 줄 기대.

## D. 예약 흐름 (확인·취소·변경, 2026-10-22)

원칙: **확인 카드의 "예약하기"와 취소 확인의 "취소하기"를 누르기 전에는 예약·취소가 일어나지 않는다.** 응급 문장은 이 흐름 어디에 있어도 119 안내(상담 경로)가 먼저다. 열 설명: 입력 = 사용자가 치거나 누른 것, 기대 = 응답·부작용, 검증 = 자동(테스트 파일) / 실서버(2026-10-22 gosky 가상 계정으로 확인) / 수동.

| # | 입력 | 기대 | 검증 |
|---|---|---|---|
| D1 | "내과 예약해줘" (날짜 없음) | 병원·진료과를 정한 뒤 **날짜를 달력으로 묻는다**. 오늘로 정하지 않는다 | 자동 `test_reservation_date_ask` · 실서버 |
| D2 | 이력에 "오늘은 예약 가능한 시간이 없어…" 같은 안내가 있는 상태에서 새 예약 요청 | 이력의 날짜를 이어받지 않고 날짜를 묻는다 | 자동 `test_reservation_date_ask` |
| D3 | 시간까지 고름 | **확인 카드**: 환자·병원·진료과·날짜·시간·가린 연락처(`010-****-1234`) + [예약하기 / 고치기]. 예약 호출 없음 | 자동 `test_reservation_confirm_cancel` · 실서버 |
| D4 | 카드에서 "예약하기" | 예약 1회, "예약이 완료되었습니다." + [예약 목록 보기 / 계속 상담하기] | 자동 · 실서버 |
| D5 | 카드가 떠 있는데 "네 예약해줘"를 직접 입력 | 카드가 다시 뜰 뿐 예약되지 않는다 | 자동 |
| D6 | 카드에서 "고치기" → 시간 선택 → 새 시간 | 병원·진료과·날짜·시간 중 고른 것만 다시 묻고 카드 재표시. **옛 시간이 이력에서 되살아나지 않는다** | 자동 |
| D7 | 고치기 중 "오후 2시로 해주세요" 직접 입력 | 카드 시간이 14:00으로 바뀐다 | 실서버 |
| D8 | 보호자가 피보호자 대신 예약 | 카드 첫 줄에 "{피보호자}님의 예약을 보호자님이 대신 잡고 있어요", 환자는 피보호자. 확인 때 wardId가 카드와 다르면 거부 | 자동 |
| D9 | "예약 취소할래" | 취소 가능한 예약(오늘 이후·날짜순 최대 10건) + [그만두기] → 선택 → "{병원} {날짜} {시간} 예약을 취소할까요?" [취소하기 / 그대로 두기]. **확인 전 취소 호출 없음** | 자동 · 실서버 |
| D10 | 남의 예약 id를 직접 보냄 | 예약 서비스 404 메시지가 그대로 나가고 취소되지 않는다 | 자동 |
| D11 | "예약 바꿔줘" → 예약 선택 → 새 날짜·시간 | 같은 병원·진료과로 이어지고 카드에 "기존 예약은 새 예약이 완료되면 취소돼요". **새 예약이 확정된 뒤에만** 기존 취소. 새 예약이 실패하면 기존 유지, 기존 취소가 실패하면 안내 후 재시도 | 자동 |
| D12 | 같은 확인 버튼을 거의 동시에 여러 번 | 예약 1건, 나머지는 "이미 처리 중이에요" | 자동 · 실서버 |
| D13 | 서로 다른 사용자가 같은 병원·같은 시간을 동시에 확정 | 1건만 예약, 나머지는 "이미 마감된 시간대" | 자동(예약 서비스 `npm test`) · 실서버 |
| D14 | 취소 목록·취소 확인·확인 카드가 떠 있을 때 "숨을 못 쉬겠어요" | **119 안내가 먼저**(상담 경로), 예약·취소 호출 없음, 대기 중이던 카드는 만료 | 자동 `test_reservation_confirm_scenarios` · 실서버 |
| D15 | "예약 잘 됐어요 취소 안 할게요" / "예약을 취소하지 않을래요" | 부정문이라 취소 목록이 뜨지 않는다 | 자동 |
| D16 | "예약 취소 방법 알려줘" / "병원 예약 변경 방법 알려줘" | 목록을 띄우지 않고 "'예약 취소할래' 또는 '예약 바꿔줘'라고 말씀해 주세요" 안내 | 자동 |
| D17 | 프로필 주소로 병원을 찾은 결과 | [다른 지역으로 찾기] 버튼 → 지역 입력. 사용자가 직접 말한 지역이면 버튼 없음 | 자동 |
| D18 | 위조·이미 쓴·다른 세션 토큰으로 확인/취소 버튼 값을 직접 보냄 | "확인 시간이 지났어요…" 안내, 예약·취소 호출 없음 | 자동 · 실서버 |

수동으로 볼 때 주의: D1·D7은 LLM 추출을 거치므로 문장에 따라 날짜·시간 해석이 흔들릴 수 있다. D3 카드의 시간·날짜가 방금 고른 값과 같은지 반드시 본다.

## 안정성 확인 방법

같은 질문을 3회 보내 `meta.router.route`, `meta.router.emergency`, `riskLevel` 이 같은지 본다. 키워드 층(A1~A10, A12, A13)은 결정적이라 항상 같아야 한다. A11·C4·C5 는 라우터 판단이라 흔들릴 수 있다 — 흔들리면 키워드 추가 또는 라우터 프롬프트에 예시 추가.
