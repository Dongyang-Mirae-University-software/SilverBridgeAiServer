# 말벗·정서 분석 안내 (팀 공유용)

> 이 문서는 **말벗(AI 동반자)과 정서 분석**이 무엇인지, 어떻게 만들었는지, 어떤 모델을 쓰는지, 테스트 결과가 어땠는지, 아직 못 한 것이 무엇인지 정리한 문서입니다.
> 처음 보는 분도 읽을 수 있게 용어를 풀어서 썼습니다. 기준 날짜는 **2026-10-25**입니다.
> 상세 진행 상황은 계획서(`plan\AI말벗_정서분석_계획서.html`)가 기준입니다. 이 문서는 그 내용을 한 곳에 모은 요약입니다.

---

## 1. 한눈에 보기

- **무엇을 만드나요?** 독거 어르신이 하루 다섯 번(9·12·15·18·21시), AI 말벗과 이야기하고, 그 대답의 **마음 상태**를 보호자에게 알려 주는 기능입니다.
- **누가 쓰나요?**
  - **어르신**: 정해진 시각에 질문을 받고, 최대 2분 동안 대화합니다.
  - **보호자**: 시각별 질문을 정하고, 하루 결과를 봅니다. "확인 필요"면 알림을 받습니다.
- **목표 날짜**: 최종 발표 **11월 24일**. 2주 전인 **11월 10일**까지 완성하는 것이 목표입니다.
- **지금 상태**: AI 쪽 기능과 테스트 화면은 로컬에서 동작합니다. 하지만 **백엔드·프론트 연결, 실제 AI 서버 연결, 실제 어르신 데이터 검증은 아직 못 했습니다.**

## 2. 용어를 먼저 알아 둡시다

| 용어 | 뜻 |
|---|---|
| 말벗 | AI가 먼저 말을 걸고, 어르신과 대화하는 기능 |
| 정서 분석 | 대답의 글과 표정으로 마음 상태를 판단하는 것 |
| STT (음성 → 글자) | 어르신이 말한 소리를 글자로 바꾸는 것 |
| 텍스트 감정 | 글자의 뜻으로 기쁨·슬픔 같은 감정을 판단하는 것 |
| 표정 감정 | 얼굴 사진으로 표정을 판단하는 것 |
| 턴 | 어르신이 한 번 대답하고, AI가 한 번 답하는 한 번의 주고받음 |
| 대화 (세션) | 한 질문에 대한 2분 이내의 대화 전체 |
| 하루 결과 | 그날 모든 대화 결과를 모아서 보여 주는 한 줄 결과 |
| CER (글자 오류율) | STT가 글자를 얼마나 틀렸는지. **낮을수록 좋습니다** |
| 확신도 | 모델이 그 답을 얼마나 확신하는지 (0~1, 높을수록 확신) |
| 1위 결과 | 여러 턴 중 **가장 많이 나온 결과** |
| 동의 | 어르신이 사진 전달에 동의했는지 여부 |
| 목업(mock) | 실제 서버 대신 흉내 내어 만든 임시 서버. 지금 테스트는 이것으로 합니다 |

## 3. 전체 흐름 (어르신 한 번의 대화)

1. **보호자**가 9시 질문을 정합니다. 예: "오늘 아침 편안하게 주무셨나요?"
2. 9시가 되면 **백엔드**가 어르신 기기에 **웹 푸시 알림**을 보냅니다. (백엔드·프론트 작업)
3. 어르신이 알림을 열면 **대화를 시작**합니다. AI 서버는 이때부터 **2분**을 셉니다.
4. 어르신이 말하거나 글로 씁니다. 말은 **음성 → 글자**로 바뀝니다.
5. AI가 **턴 결과**를 냅니다.
   - 글자로 감정을 봅니다.
   - 글자가 좋으면 그대로 넘어갑니다.
   - 글자가 나쁘거나 애매하면, **표정도 봅니다.** 같은 순간에 사진 3장을 읽고 가장 많이 나온 표정을 씁니다.
6. AI가 **공감 한 문장과 꼬리질문 한 문장**을 말합니다. 최대 **8턴**까지 이어갑니다.
7. 2분이 지나거나 8턴이 되거나 어르신이 끝내면 대화가 끝납니다. **대화 결과**는 1위 결과와 전체 구성으로 보여 줍니다.
8. 하루 동안의 대화가 모여 **하루 결과**가 됩니다. "확인 필요"가 1위면 보호자 화면에서 알려 줍니다.
9. 확인 필요 턴에서 **동의가 있을 때만** 얼굴 사진 한 장이 백엔드로 전달됩니다. 백엔드가 저장하고, 보호자가 볼 수 있게 할지는 나중에 정합니다.

## 4. 판단 규칙 (사용자 결정 사항)

### 4-1. 한 턴의 결과 (말을 먼저 봅니다)

| 말의 판단 | 표정 판단 | 턴 결과 | 이유 |
|---|---|---|---|
| 기쁨 | (보지 않음) | 기쁨 | 말이 좋으면 넘어갑니다 |
| 평온 | (보지 않음) | 평온 | 말이 좋으면 넘어갑니다 |
| 부정 | 긍정 | 판단 보류 | 말과 표정이 엇갈립니다 |
| 부정 | 부정 또는 애매 | 확인 필요 | 말이 부정이면 보호자가 확인합니다 |
| 애매 | 부정 | 확인 필요 | 말은 애매해도 표정이 부정이면 확인합니다 |
| 애매 | 긍정·중립 | 판단 보류 | 확실하지 않으니 다음 질문으로 확인합니다 |
| 애매 | 애매 | 확인 필요 | 둘 다 확실하지 않으면 보호자가 확인합니다 |

- **확인 필요는 진단이 아닙니다.** 보호자가 한 번 더 살펴보라는 신호입니다.
- 표정 사진은 한 턴에 **3장을 1초 간격**으로 읽고, **가장 많이 나온 표정**을 씁니다.

### 4-2. 대화 결과와 하루 결과 (1위 규칙)

- 결과 라벨은 **1위**입니다. 예: 기쁨 3, 확인 필요 1 → **기쁨**.
- **동점 1위** 중에 확인 필요가 있으면 확인 필요, 없으면 판단 보류입니다.
- 옆에 **전체 구성**을 함께 보여 줍니다. 예: `기쁨 3회 (50%) · 확인 필요 1회 (17%) · 판단 불가 1회 (17%)`
- "분석 실패"와 "판단 불가"는 **비율 계산에서 뺍니다.** 정해진 턴이 하나도 없으면 "판단 불가"입니다.
- 하루 결과도 **같은 규칙**을 씁니다.

### 4-3. 대화의 제한

- 한 질문당 대화는 **최대 2분**입니다. 서버가 시작 시각부터 셉니다.
- 꼬리질문은 **최대 8턴**입니다. (사용자 확정, 2026-10-25)

### 6-3. 어르신 실제 목소리 + 잡음 (이번 시험)

> 공개 데이터의 실제 어르신 발화 12문장. 이전 평가에서 쓴 음성이라 "완전히 새 음성"은 아닙니다.

| 조건 | 평균 CER | 중간값 | 10% 이하로 맞힌 비율 | 해석 |
|---|---|---|---|---|
| 원래 소리 | 5.7% | 0% | 67% | 조용하면 잘 알아듣습니다 |
| 잡음 10dB | 10.2% | 8.3% | 58% | 조금 틀립니다 |
| 잡음 5dB (여럿이 떠드는 수준) | **30.3%** | 17.4% | 33% | 실사용에서 흔한 수준이라 위험합니다 |
| 느린 말 (0.85배) | **64.1%** | 74.2% | 25% | 가장 어렵습니다. 음높이도 함께 낮아져서 실제보다 과장됐을 수 있습니다 |

**결론**: 조용한 곳에서는 쓸 수 있지만, 잡음이나 느린 말이 섞이면 **인식이 크게 틀립니다.** 그래서 "인식이 어려우면 글로 적어 주세요"라는 안내와, 틀린 글자를 고칠 방법이 필요합니다. (아직 없음)

### 6-4. 파인튜닝 (AI Hub 86 노년 데이터로 학습)

| 항목 | 학습 전 | 학습 후 | 판단 |

| 시험 | 데이터 | 결과 | 해석 |

## 7. 이 브랜치에서 한 것 (AI 서버)

- **말벗 전용 읽기 키**(`COMPANION_STREAM_API_KEY`): 말벗이 최신 프레임과 상태만 읽을 수 있게 했습니다. 비워 두면 꺼져 있습니다.
- **경로별 인증**: 라우터 전체에 걸던 인증을 경로마다 나눴습니다.

  - 메인 키만 허용: 나머지 스트림 경로 7개
- **헤더 전용**: 키는 `X-API-Key` 헤더로만 받습니다. 주소(쿼리스트링)에 키를 넣는 방식은 막았습니다.
- 말벗 본체(질문, 대화, 판단, 화면)는 `app/companion/`에 있습니다. 시험은 `tests/companion/`에 있습니다.
- 말벗 API는 AI 서버 Swagger(`/api/docs`)에 `말벗 (Companion)` 태그로 나타납니다.

## 8. API 정리

모든 요청에 `X-API-Key` 헤더가 필요합니다. 응답은 `{success, message, data, code}` 형식입니다.

### 8-1. AI 서버 (이 브랜치)

| 메서드 | 경로 | 허용 키 | 설명 |
|---|---|---|---|
| GET | `/api/v1/live-streams/{session_id}/latest-frame` | 메인 또는 말벗 | 최신 JPEG 프레임. 저장하지 않고 읽기만 |
| GET | `/api/v1/live-streams/{session_id}/status` | 메인 또는 말벗 | 세션 상태 (`status`, `lastFrameAt`, `fps`, `viewerCount`, `isAnalyzing`) |
| 그 밖의 스트림 경로 | `/api/v1/stream-sessions...`, `/api/v1/live-streams...` | 메인만 | 기존 동작 그대로 |

### 8-2. 말벗 API (`/companion` 경로, AI 서버 Swagger 의 말벗 항목)

**질문과 예시**
- `GET /companion/question?wardId&slot`: 시각의 질문 조회
- `PUT /companion/questions/{slot}?wardId`: 질문 저장 (`{"question": "..."}`, 200자 이내)
- `GET /companion/examples`: 카테고리별 예시 질문

**대답 한 번 (대화 없이)**
- `POST /companion/answers`: 글 대답 `{wardId, sessionId, slot, text, faceCheckSec}`
- `POST /companion/answers/audio`: 음성 대답 (multipart: `wardId, sessionId, slot, audio`)

**대화 (최대 2분, 최대 8턴)**
- `POST /companion/dialogues` `{wardId, sessionId, slot}`: 대화 시작. 응답에 `dialogueId`, 질문, 제한 시간(120초)
- `POST /companion/dialogues/{id}/reply` `{text, face?, consentPhoto?, photo?}`: 글 대답. 응답에 `label`, `reason`, `reply`, `done`, `secondsLeft`, `photoForBackend`
- `POST /companion/dialogues/{id}/reply/audio` (multipart: `audio, faceLabel, faceScore, consentPhoto, photo`): 음성 대답. 응답에 `transcript`
- `POST /companion/dialogues/{id}/finish`: 대화 종료. `sessionLabel`, `summary`, `distribution`, `turns`

**표정과 결과**
- `POST /companion/expression-check` (multipart: `frame`, JPEG 2MB 이하): 사진 한 장의 표정
- `GET /companion/emotions?wardId&date`: 하루 결과 (`dayResult`, `summary`, `distribution`, `items`)

**검수 (관리자)**
- `GET /companion/review/replies?status=pending|approved|rejected`: AI가 만든 문장 목록. 어르신 대답 원문은 없음
- `POST /companion/review/replies/{id}` `{decision: approved|rejected}`

**주의**: 지금 말벗 API는 **목업**입니다. 대화 상태와 검수 목록은 메모리와 파일에 저장되고, 서버가 꺼지면 사라집니다. 실제 서비스에서는 DB가 필요합니다.

## 실행 방법 (AI 서버 안에서)

1. AI 서버 `.env`에 `COMPANION_API_KEY`(말벗 API 키)와 `COMPANION_STREAM_API_KEY`(말벗 읽기 키)를 넣습니다. 값은 직접 만들어서 넣고, 채팅이나 문서에 적지 않습니다.
2. 말벗 음성·표정 기능에 필요한 라이브러리를 설치합니다 (`requirements.txt` 의 말벗 항목).
3. 서버를 켜면 Swagger 의 `말벗 (Companion)` 항목에서 경로를 확인할 수 있습니다.
4. 시험: 저장소 루트에서 `pytest tests/companion --noconftest` (말벗 가상환경에서 실행하는 것을 권장합니다).
5. 독립 실행(목업 서버): `app/companion` 폴더에서 `uvicorn api_mock:app --port 8765`

주의: 음성 인식 모델(large-v3)과 표정 모델은 처음 켤 때 내려받거나 읽는 데 시간이 걸립니다. AI 서버의 기본 시작 과정(MedGemma 로드)도 함께 필요합니다.

## 9. 개인정보와 동의 (가장 중요)

- **음성은 저장하지 않습니다.** 글자로 바꾼 뒤 버립니다.
- **표정 사진은 저장하지 않습니다.** 확인 필요 턴에서 **동의가 있을 때만** 한 장을 백엔드로 전달합니다.
- **서버 기본값은 꺼짐입니다.** 화면의 체크 칸은 **테스트용으로 기본 켜짐**입니다. 실제 제품에서는 어르신이 직접 동의하는 화면이 있어야 합니다.
- **보관 기간**: 30일 이내로 정하셨습니다. 정확한 기간과 저장 방식은 8.4에서 최종 확정합니다.
- **대화 기록**: 백엔드 DB에 저장하는 것으로 결정했습니다. 나머지 기능을 다 만든 뒤에 구현합니다.
- **카메라 영상**: 저장하지 않습니다. 대화 중 얼굴 확인은 하되, 결과와 확인 필요 턴의 사진 한 장만 남깁니다.
- **AI Hub 데이터**: 비상업 연구용입니다. 이 데이터로 만든 모델도 같은 조건을 따릅니다.

## 10. 파트별로 알아야 할 것 (초보자용)

### 10-1. AI 파트 (이재희 담당)
- 말벗 본체와 정서 분석 로직은 `app/companion/`에 있습니다. 실행 방법은 아래 "실행 방법" 절을 보세요.

  - 인식이 어려울 때 확인 질문을 하는 흐름 추가
  - 최종 측정과 시연 리허설 (실제 서버 연결 후)
  - 대화 기록 DB 연결 (백엔드 저장 구조 확정 후)

### 10-2. 백엔드 파트
- **질문 저장**: 보호자가 정한 시각별 질문을 DB에 저장합니다. (Q1, 7.2)
- **시각에 맞춰 알림 발송**: 정해진 시각에 웹 푸시를 보냅니다. (Q10)
- **대화 중계**: 프론트가 보낸 대답을 AI 서버로 넘기고, 결과를 받아 저장합니다. (Q2~Q9)
- **사진 저장**: 확인 필요 턴의 사진을 파일 저장소에 두고, DB에는 경로만 저장합니다. (Q13)
- **대화 기록 저장**: 턴별 글과 결과를 DB에 저장합니다. (Q14, 나중)
- **관리자 권한 확인**: 검수 목록은 **관리자 계정만** 볼 수 있어야 합니다. AI 서버는 키만 확인하므로, 백엔드가 관리자인지 먼저 확인하고 호출해야 합니다.
- **2분 시간 계산**: AI 서버가 이미 셉니다. 백엔드는 따로 재지 않습니다. (Q11 제안)

### 10-3. 프론트엔드 파트
- **어르신 화면**: 시각 선택, 질문, 대화, 2분 타이머, 말하기, 카메라, 동의 화면. 프로토타입은 `app/companion/ui/product`에 있고, 서버를 켜면 `/companion/ui/product/`에서 열립니다.
- **보호자 화면**: 시간표, 오늘의 마음, 질문 설정, 실시간 전달 기록, 하루 결과. 프로토타입 있음.
- **웹 푸시 구독**: 기기에서 알림 권한을 받고, 구독 정보를 백엔드에 보냅니다.
- **관리자 검수 화면**: AI 문장을 승인·반려하는 화면.
- **사진 동의 화면**: 어르신이 직접 켜고 끌 수 있어야 합니다. 프로토타입의 체크 칸은 테스트용입니다.
- **앱인지 웹인지**: 아직 정하지 않았습니다. 웹 푸시를 쓰므로 웹(PWA)을 먼저 만드는 것이 단순합니다. 최종 결정은 사용자님과 프론트가 함께 정합니다.

### 10-4. 사용자(팀 대표·결정권자) 결정 필요
- 앱 제작 방식 (DL.13)
- 사진 보관 기간과 저장 위치, 학습 가중치 저장 위치 (5.완료b, 8.4)

- 발표 날짜 확인과 시연 준비
- 서버 주소, 말벗 키 전달 (서버 담당자와 협의)

### 10-5. 팀 전체
