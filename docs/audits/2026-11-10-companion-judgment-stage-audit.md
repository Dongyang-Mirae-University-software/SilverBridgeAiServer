## 이슈

### 🔴 H-1. 위험 판정이 생성 작업 뒤에 줄을 서서 시간 초과된다 (#206 회귀)
- 위치: `llm_client.py:64-68`(문 입장 조건), `llm_client.py:92-99`(시간 제한이 문 앞 대기를 포함), `pipeline.py:163-166`, `risk.py:46,63`(예외를 로그 없이 삼킴)
- 원인: 한 턴은 신호(기본)·대답(`reply`)·요약(기본)·위험(기본)을 함께 보낸다. 다른 어댑터를 기다리는 호출이 있으면 같은 어댑터 호출도 새로 들어가지 못하므로, 위험(0.11초짜리)이 신호 생성 → 대답 생성이 끝날 때까지 기다린다. 25초 제한에는 이 대기가 들어간다. 위험이 None이면 신호 JSON의 riskFlag로, 신호도 실패하면 낱말 규칙으로만 정한다. #206 전에는 모두 기본 모델이라 이런 줄이 없었다.
- 재현(시간 1/100 축소, 위험 모델은 늘 0.999 "있음"):
  - 대답 생성이 반복 고리로 30초 → 위험·요약·기분 모두 시간 초과, riskFlag=False
  - 대답 1초·위험 0.11초(DGX 측정)·신호 3초(가정), 6명이 0.5초 간격 → 위험 3/6 놓침, 기분 4/6 시간 초과, 턴 20~30초
  - "이제 다 내려놓고 영감 곁으로 가고 싶어"(낱말 규칙에 안 걸림)가 riskFlag=False
- 수정: ① 위험(0.11초)·기분(0.07초) 확률을 생성 작업보다 먼저 계산(턴 순서 [위험] → [기분] → [신호·요약] → [대답]) ② 문 대기 시간을 시간 제한과 분리하거나 확률 호출에 문 우선권 ③ 위험 계산 실패에 WARN 로그(클래스명만)
- 고정 테스트: 실제 `AdapterGate` + sleep 가짜 `ExaoneLlm`로 대답 생성 시간 합이 제한을 넘어도 `riskFlag=True`

### 🟠 H-2. 어댑터 하나만 적재에 실패하면 기본 모델에 기분 LoRA가 켜진 채 남는다
- 위치: `llm_client.py:132-157`
- 원인: `PeftModel.from_pretrained`는 원본 모델 안에 LoRA 층을 직접 끼운다. 두 번째 `load_adapter`가 실패하면 except에서 `_adapters=set()`으로 두고 원본 `model`을 돌려주는데, 거기에는 `mood` LoRA가 켜진 채 남고 `_switch`는 아무것도 하지 않는다.
- 재현: 깨진 두 번째 어댑터 → 로그는 "LoRA adapters not loaded"뿐, 돌려받은 모델에 LoRA 모듈이 남고 깨끗한 기본 모델과 logits가 최대 0.385 다름. 위험·신호·요약이 모두 기분 LoRA로 계산된다.
- 수정: except에서 `peft_model.unload()`로 걷어낸 뒤 돌려주거나, 성공한 어댑터만 `_adapters`에 넣고 `disable_adapter_layers()`
- 고정 테스트: 작은 모델 + 깨진 두 번째 어댑터로 `_attach_adapters` 뒤 기본 출력이 깨끗한 모델과 같음
