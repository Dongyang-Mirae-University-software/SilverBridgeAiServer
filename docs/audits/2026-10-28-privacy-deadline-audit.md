## 이슈

### 🟡 M-1 이어 쓰는 턴에서 저장 초안의 지역이 전체 주소로 Claude에 나간다
- 위치: `app/services/reservation_orchestrator.py` `_extract_reservation_fields` - `draft_state`의 `facts.location`을 `[현재 상태 JSON]`에 그대로 싣는다.
- 원인: 첫 턴은 프로필·위치 힌트를 시·구까지로 줄였지만, 초안의 `location`은 서버 검색용으로 전체 값(`context.location` 또는 `address`, 또는 사용자가 입력칸에 친 값)을 그대로 들고 다닌다. R-8 이후 다음 턴은 이 초안을 이어 쓰므로 두 번째 문장 턴부터 전체 주소가 나간다. 변경 흐름(`reservation_change_pick` → 문장 턴)도 같다.
- 재현: `context={"address": "서울특별시 강남구 테헤란로 123"}`로 "근처 내과 예약해줘" → 병원 목록(초안 저장) → 라우터 문장 "병원 예약: 내과 / 모레" + 원문 "모레로 해줘" → 두 번째 추출 프롬프트에 "테헤란로"가 있다. 변경 흐름도 같은 결과.
- 노출 범위: 실제 FE(`ChatbotContent.tsx`)는 `context`에 주소·위치를 보내지 않는다(본인 상담은 `role`만, 대리 상담은 피보호자 이름·전화·생년월일 등). 그래서 지금은 **사용자가 지역 입력칸에 전체 주소를 쳤을 때만** 일어난다. 그 문장은 원래 라우터로도 나가지만, S-6 의도(추출에는 시·구까지만)와 다르다. BE·FE가 나중에 주소를 싣기 시작하면 모든 이어 쓰는 턴에서 나간다.
- 고치는 방향: `facts.location`에도 `coarse_region`을 적용한다(초안 자체의 값은 검색용으로 그대로 둔다). 테스트: 주소만 있는 프로필로 두 번째 문장 턴 추출 입력에 도로명이 없음(일반 흐름·변경 흐름).

### 🟢 L-1 확인 버튼 턴에서 예약 계정 확보 중 마감에 걸리면 확인 카드가 만료된다
- 위치: `app/services/chat_service.py` 예약 분기 `except ChatDeadlineExceeded` - 다음 턴에 넘기는 것은 `flowState`뿐이고 `pendingAction`은 넘기지 않는다.
- 영향: 마감에 걸린 지점이 토큰 선점 **전**(`ensure_credential`)이라 예약은 만들어지지 않는다. 사용자가 같은 버튼을 다시 누르면 "확인 시간이 지났어요"로 처음부터 다시 해야 한다. 예약 계정 확보가 110초를 다 쓰는 경우라 드물다.
- 고치는 방향: 선점 전이므로 `pendingAction`도 그대로 넘기면 같은 버튼으로 다시 시도할 수 있다(토큰 선점이 중복을 막는다).

### 🟢 L-2 국제 형식 전화번호는 가려지지 않는다

- 반대로 `0`으로 시작하는 10자리 숫자(예: "0123456789")는 전화로 가려지는데, 판단에 영향은 없다. 날짜·시간·대표번호(1588-1234)는 가려지지 않음을 확인했다.

### 🟢 L-3 추출이 줄인 지역을 돌려주면 "다른 지역으로 찾기" 버튼이 사라질 수 있다

## PASS로 확인한 것

- **되돌릴 수 없는 호출 순서**: 생성은 토큰 선점 전·생성 직전 두 번 남은 시간을 본다. 선점 뒤 시간이 모자라면 새 토큰 카드를 주며 생성은 부르지 않는다 → 같은 예약이 두 번 생기지 않는다. 생성 호출 자체가 시간 초과로 결과 불명이 되는 경우는 #88 전과 같고, 예약 서비스의 사용자 `(userId, 날짜, 시간)` 유일 인덱스가 다시 눌러도 중복을 막는다. 취소 확인·변경 흐름의 기존 예약 취소도 같은 검사를 거친다.
- **예외 삼킴**: `_booked_times`가 `ChatDeadlineExceeded`를 삼키지만, 뒤의 생성 직전 검사·빈 시간 조회가 다시 잡는다 - 엉뚱한 안내로 새지 않는다.
- **contextvar 경계**: 마감은 `process_message`의 `with` 블록에서 설정·해제된다(예외 포함). 엔드포인트는 동기 함수라 스레드풀 스레드에서 돌고, 챗 처리 안에 다른 스레드로 넘기는 호출이 없다. 다음 요청에 이전 마감이 붙지 않는다. 챗 밖(예약 계정 API·관리 API·OCR)은 마감이 없어 예전 상한 그대로다.
- **최악 합계 재계산**: 증상 상담 = 라우터 60 + 0.5 + 재시도 19.5 → 80초, 남은 30초 < 생성 최소 30.5초라 고정 문구 → 약 80초. 예약 문장 = 라우터 최대 80초 → 남은 30초 안에서 계정·추출(최대 15초)·API(각 남은 시간 - 2초) → 110초 안. 확인 버튼 = 라우터 없음, 생성은 남은 25초 이상일 때만 → 110초 안. 넘칠 수 있는 것은 시작한 생성(최대 약 30초)과 소켓 단위 제한뿐이다(결과 문서에 적은 대로).
- **응급·자해**: 자해 키워드 고정 응답은 Claude·MedGemma를 부르지 않아 마감과 무관하다. 응급 턴에서 생성할 시간이 없으면 119·경고 박스·high 고정 문구다(테스트 고정).
- **로그**: `[CHAT-DEADLINE]`은 단계 이름(경로는 숫자 ID를 `{id}`로)과 남은 ms만. Claude 실패 로그는 상태 코드·모델·시도 회차만. 문장·이름·전화·주소 원문 없음.
- **동작 보존**: 증상 요약은 이어 쓰는 문장 턴에서 덧붙고 새 요청에서 새로 만들어진다. 변경 흐름은 빈 값에서 시작한다.
