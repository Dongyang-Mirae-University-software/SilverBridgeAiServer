# MedGemma 8비트(int8) 재측정 - 1단계에서 멈춤 (2026-10-26)

- 목표(사용자 결정): 품질은 16비트 수준 유지, 속도는 양보 가능, EXAONE(약 2.5GB)을 함께 올려도 gosky GPU 여유 1.5GB 이상.
- 코드: #60 `MEDGEMMA_QUANT=int8`(`BitsAndBytesConfig(load_in_8bit=True)`, 실패 시 none 폴백). 기본 none이라 머지만으로는 동작이 같다.
- 단계별 관문: 1단계(무료, DGX, 라우터 없이 MedGemma 직접) → 통과 시에만 2단계(유료, gosky run_eval v4 1회). 멈춤 조건은 ① 파싱 실패·권고 기본 문장 대체가 bf16보다 나쁨 ② GPU 여유(EXAONE 포함) 1.5GB 미만, 둘뿐이다.
- 결과 원본 `2026-10-26-int8-retest.json`(본문 없음, 답변 본문은 DGX 밖으로 옮기지 않음).

## 1단계 - DGX GB10, 시험지 v3 단일 턴 의료 20문항 × 1회 (greedy)

문항: qa.A1·A7·B1·B3·C1·C4·D3·D5·E1·E4·F1·F3, md.S8·M3, em.05·06·10, bd.02·03, px.01(응급 7). nf4에서 실패했던 qa.A7·qa.B1·em.05·bd.03을 넣었다. bf16은 같은 날 DGX `nf4tail_a.json` 1회차의 같은 20문항을 재사용했다(다시 재지 않음).

| 항목 | bf16 | int8 |
|---|---|---|
| JSON 파싱 실패 | 0 | **1** (qa.D5) |
| 상한(512) 도달 | 0 | **1** (qa.D5) |
| 권고가 서버 기본 문장으로 대체 | 0 | **1** (qa.D5) |
| 응급 7건 모델 119 문장 / 경고 박스 | 7 / 7 | 7 / 7 |
| 예시 단어 복사 | 1 | 1 |
| 생성 토큰 평균 | 113.8 | 130.6 |
| 생성 시간 평균 / 최대(초) | 6.67 / 8.47 | 8.74 / 33.61 (실패 건 빼면 평균 7.43) |
| 가중치 / torch 최대 할당(GB) | 8.01 / 8.28 | 4.67 / 4.98 |

- qa.D5(복약): advice 칸에서 8자 조각이 15번 되풀이되는 반복 고리에 빠져 512토큰 상한까지 갔다(33.6초). nf4 실패(10/23·10/26 DGX)와 같은 종류다.
- 메모리는 기준을 넉넉히 통과한다(어림: gosky에서 약 5.6GB, EXAONE 2.5GB를 더해도 약 4GB 여유). 속도도 기준 안이다(생성 +31%, 라우터 약 3초를 더해도 평균 15초 이하, 최대 60초 이하).

## 판정

- **1단계 멈춤 조건 ①에 걸려 미채택.** 파싱 실패·기본 문장 대체가 bf16(0)보다 많다(1). 품질을 16비트 수준으로 유지한다는 목표에 맞지 않는다.
- 2단계(gosky run_eval·판정자 채점)는 하지 않았다. **gosky 재시작 0회**, `.env`·코드 변경 없음(gosky `3944343`, `MEDGEMMA_QUANT=none` 그대로).
