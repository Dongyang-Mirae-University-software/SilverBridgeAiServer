# 증상 상담 되묻기 설계 (C-1) - 2026-10-29

> **구현 상태**: 설계만 한다(2026-10-29, 결정 질문 Q1~Q5 답을 받은 뒤 구현). 이 문서 시점에 코드는 바뀌지 않았다. 근거는 main `b81b570` 기준 코드(`chat_service.py`·`medical_llm_service.py`·`medical_chat_prompts.py`·`chat_router_service.py`)와 BE `docs/(2026-10-20) analysis-ai-chat-reservation.md` 3-3절 C-1.

## 1. 문제

증상 상담 답은 한 틀(공감 · 증상 정리 · 특징 · 진료과 권고)뿐이다. **언제부터·얼마나 심한지·같이 나타나는 증상**을 묻지 않아 진료과를 고른 근거가 약하고, 판정자 채점의 필수 항목(조건부 진료 시점·경고 신호)이 답에 들어갈 재료가 없다. "어지러워요" 한 마디에도 "신경과 진료를 권해드려요"로 끝난다.

**하고 싶은 것**: 정보가 부족한 일반 증상 질문에 한 번만 짧게 되묻고, 다음 턴의 답으로 상담을 마무리한다.
**하지 않을 것**: 응급·위기 대응을 늦추는 것, 답을 되묻기로만 끝내 버리는 것, 같은 질문을 반복하는 것.

## 2. 지금 흐름에서 되묻기가 들어갈 자리

| 단계 | 지금 | 되묻기와의 관계 |
|---|---|---|
| 자해 키워드 → 고정 응답 | 라우터보다 먼저 | **절대 되묻지 않는다** - 그대로 |
| 라우터(Claude) | route·emergency·self_harm·symptom_summary | 되묻기 필요 여부를 같이 판단할 수 있다(칸 추가) 또는 서버 규칙으로 정할 수 있다 |
| 응급 강제(`_force_emergency`) | 키워드·라우터 응급이면 119 안내 | **되묻지 않는다** |
| 예약 흐름 | 진료과·병원·날짜를 UI로 묻는다 | 이미 묻는 흐름이 있다 - 되묻기 대상 아님 |
| MedGemma 상담 | 한 번에 답 | 되묻기 턴은 MedGemma 대신 고정 질문(빠름)이나 MedGemma 짧은 질문 |
| 서버 이력(S-7) | 같은 사용자·세션·wardId `chat_logs` 24개 | 다음 턴이 앞 질문과 답을 그대로 본다 - 이어 붙이기에 따로 저장할 것이 거의 없다 |
| 직전 턴 meta(`_previous_turn_meta`) | 위기 표시(selfHarm·crisisFollowup)를 다음 턴이 읽는다 | 같은 방식으로 `followupAsked` 표시를 두면 "이번 턴은 되묻기의 답"을 안다 |

## 3. 제안 (A안 - 서버 규칙 + 고정 질문)

1. **언제 되묻는가**: 아래를 모두 만족할 때만.
   - 라우터 route = symptom, emergency = false, self_harm = false, 위기 뒤 턴(`crisisFollowup`)이 아님
   - 약 문의(약 + 묻는 표현)·약 + 술·생활관리 질문이 아님(이미 상의 안내가 정답인 질문)
   - 질문에 기간(어제부터·며칠째·일주일 등)과 정도·동반 증상 표현이 **모두 없음**(규칙 판정 - 라우터 요약을 쓰지 않는다)
   - 같은 세션 직전 턴이 되묻기가 아님(**세션당 연속 1회**)
2. **무엇을 묻는가**: 고정 질문 한 줄 + 바로 쓸 수 있는 짧은 안내. 예) "언제부터 그러셨는지, 같이 나타나는 증상(열·통증 등)이 있는지 알려 주시면 더 정확히 안내해 드릴게요. 갑자기 심해지면 바로 119에 연락하세요." 답 틀(공감·증상 줄)은 쓰지 않고 `riskLevel`은 지금 규칙 그대로.
3. **다음 턴**: 직전 meta `followupAsked=true`면 이번 문장을 앞 질문과 합쳐(서버 이력에 이미 있다) 라우터·MedGemma에 넘긴다. 사용자가 답하지 않고 다른 말을 하면 그냥 그 말대로 처리한다(되묻기 상태를 끌고 가지 않는다).
4. **응답 필드**: 그대로(`reply`만). 되묻기 여부는 `upstreamMeta.followupAsked`(기록용)로만 남긴다. BE·FE 변경 없음.

**B안 - 라우터가 판단**: 라우터 스키마에 `needs_followup` 칸을 더한다. 판단은 더 자연스럽지만 라우터 프롬프트·스키마 변경이라 위기 판정(self_harm) 재측정이 필요하고, 라우터 실패 시 판정이 사라진다. A안으로 시작하고 측정 뒤 비교하는 것을 권한다.

## 4. 위험과 막는 방법

| 위험 | 막는 방법 |
|---|---|
| 응급을 되묻기로 늦춤 | 응급·자해·위기 뒤 턴은 조건에서 제외(코드 순서상 응급 강제 뒤에서만 판정), 되묻기 문장에도 119 한 줄 |
| 같은 질문 반복(답답함) | 세션당 연속 1회, 직전 턴 meta로 확인 |
| 고령 사용자가 대답하지 않고 떠남 | 되묻기 턴에도 진료과 한 줄을 넣을지 결정 질문 Q2 |
| 다음 턴 답이 짧아("어제부터요") 라우터가 general로 보냄 | 직전 meta가 followupAsked면 앞 질문과 합친 문장으로 라우팅 |
| 시험지·판정 기준과 맞지 않음 | 다중 턴 시험지 추가 필요(아래) - 단일 턴 문항은 되묻기 턴만 보고 필수 항목이 비어 점수가 떨어진다 |

## 5. 측정

- 새 시험지(v7): 정보 부족 단일 턴 10문항 + 같은 질문에 답을 이어 주는 2턴 문항 10쌍(`replay` 사용) + 되묻지 말아야 할 반례(응급·자해·약 문의·기간이 이미 있는 질문) 10문항.
- 자동 확인: 되묻기 발생률(대상/반례), 응급·자해 결과 유지, 2턴째 답의 진료과 일치·병원 권유.
- 판정자: 2턴째 답만 기준표로 채점(같은 질문에 한 번에 답한 현재 버전과 비교), 3회 반복.
- 시간: 되묻기 턴은 MedGemma를 부르지 않으면 1턴이 빨라지고, 상담 전체는 1턴 늘어난다.
